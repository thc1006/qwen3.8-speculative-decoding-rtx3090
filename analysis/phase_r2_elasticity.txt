--- the bandwidth lever is clean here ---
  memory bandwidth @ core ~1200 MHz: core clock 1200 to 1200 MHz across the sweep, a spread of 0.00 %.
  memory bandwidth @ core ~1710 MHz: core clock 1708 to 1710 MHz across the sweep, a spread of 0.10 %.
  The core clock is pinned rather than left to fall out of a power cap, so raising
  the memory clock does not take budget from the core and there is no cross term
  to remove. Phase R needed that correction; this run does not.

  spread is between methods at the same condition; drift is within an arm,
  measured as mean minus min, so 0.00 % means every sample sat on the pin.
  The 5 matched condition(s) give intervals that span the same
  clock range for every method, so those elasticities are directly comparable.
  Where a condition is not matched the pin did not bind, because the power
  limit did first. Check the power column in the operating points above: an
  arm whose peak draw reaches the cap cannot hold its requested clock, and a
  speculative arm reaches it sooner because it draws more at the same clock.
  Elasticities crossing such a condition carry that mismatch; ones that do
  not, do not. Phase R, for contrast, was 30.0 % and 35.8 % mismatched.
